# Working a ticket through dev and CR

Read this before writing code against a ticket, and before carrying it out of In Dev.

1. A requirement discovered in CR is a **new ticket or a TR amendment - never a CR comment**. Every backward move is handled by the `cockpit:ticket:x:back-from-column` skill, which increments the counter, writes a structured summary to the ticket page, posts a short comment, and sets status. **Working through unresolved CR comments is the same case.** The card sits In CR throughout, so no move fires; the `cockpit:ticket:4:cr:comments` skill records each confirmed fix itself, one bounce per group of comments sharing a root cause - never one per comment, never one per review round. A rejection raised in chat is a bounce-back too - that half is in the always-loaded rules, which fire with no skill invoked.
2. Reviewing is the first job, building is the second: the daily plan starts with "what will I review today". WIP limit of 2 on In CR.
3. Mid-dev divergence from the tech steps is in the always-loaded rules - it fires while dev is running, with no skill invoked to load this file.
4. **In CR by AI is where the machine gates run, and they run before the push**: the card advances there the moment dev is done, the review executes against the branch as it stands on the machine, and its findings are fixed there. Nothing leaves the machine carrying a finding the gates already named, and the review never waits on a PR to write onto. Clean gates then fire `/cockpit:ticket:4:ready-for-cr`, which pushes, opens the PR and links it, with the card already in the column. A card that arrives back here with a PR already linked has its findings posted onto it as inline comments instead. Tests, lint and the ticket's validation script are meant to run there too and do not yet - do not claim they did. Human CR then verifies against the approved TR, not by mentally executing the diff.
5. **Timebox success = zero uncertainty**, and no premature wrap-up. Both are in the always-loaded rules - they fire while the timebox is being worked, with no skill invoked to load this file.
6. Keep working (research, verify, confirm) until all uncertainty is resolved, the timebox expires, or what is left is genuinely unresolvable within it.
